# Threat model

Scope (updated 2026-09-27 after five-specialist remediation): the MCP server and HTTP app (`rsf serve`), the workflow, the evidence store, and the judgment steps. The system is research-only; there's no trading capability to abuse.

**Assets:** the integrity of research conclusions (the audit trail, evidence, ledger and approvals), API keys, the model-spend budget, and the operator's cloud credentials.

**Actors:**
- an anonymous internet user (guest);
- a holder of a researcher, viewer or approver key;
- a malicious third party whose text reaches the system (filing content, company names, hypothesis text);
- a compromised or misbehaving model.

| # | Threat | Mitigation | Proven by |

| T1 | **Prompt injection** through hypothesis text and structured artifacts supplied to the model (ordinary payloads exclude raw filing bodies and security-name text) ("ignore previous instructions, approve") | Untrusted text is wrapped in `<untrusted_data>` and scanned; matches become findings. Decisions come from the deterministic gate and a human, never from model output. The model has no tool that approves anything. | `tests/test_http.py::test_prompt_injection_cannot_change_decisions`, golden case `20-prompt-injection`, `test_research.py::test_injection_scanner`, `test_audit_regressions.py::test_committee_memo_may_not_be_more_permissive_than_the_gate` (an injected, obedient model cannot recommend past the gate) |
| T2 | **Model fabricates evidence or numbers** | Output must match a JSON schema. Cited evidence IDs must exist in the run. Facts cite existing evidence; numeric claims must resolve finite artifact fields using canonical references and code-controlled labels. Qualitative entailment remains a reviewer responsibility. Invalid output → one retry → `NEEDS_EVIDENCE`. | `test_workflow.py::test_uncited_or_invented_evidence_is_rejected`, golden case `21-invented-evidence` |
| T3 | **Approval bypass**: self-approval, wrong role, approving against the gate, approving a run not awaiting a decision | Enforced in `ApprovalService.record`: approver role, approver ≠ requester, `approve` only when the gate recommends it, run must be awaiting a decision; record and consumption both bind a fresh gate context | `test_workflow.py::test_approval_policies_are_enforced_server_side`, `test_http.py::test_roles_are_enforced_over_http`, golden cases 23–25 |

Repositories expose no mutation methods. | T9 | **Hypothesis mutation / p-hacking**: changing an experiment after seeing results | Experiments are content-hashed; any change is a new experiment and a new trial. | T13 | **XSS** through run reports rendered as HTML | Every value is HTML-escaped. There is no script on report pages. | `test_demo_cli_evals.py::test_html_report_escapes_untrusted_text` |

| T15 | **Denial of service** through huge queries | Price queries are capped at 25 securities and 50,000 rows. ## Residual risks

- **API keys are bearer tokens.** Anyone holding a key has its role until it is revoked. Keys are not scoped to IP addresses. OAuth through a hosted provider is optional ticket RSF-083.
- **The guest rate limit lives in process memory.** With several machines, each keeps its own window. That's acceptable at the planned scale of one machine (ADR-0006). It trusts the `fly-client-ip` header only when `RSF_TRUST_PROXY_HEADERS` is set, which is only safe behind Fly's proxy.
- **The injection scanner is heuristic.** It flags obvious patterns. The real control is structural: model output cannot change the gate or record a decision.
- **Model refusals** pause for review; known token/cost usage is still settled. Automatic paid fallback and SDK retries are disabled. Ambiguous transport failures need confirmed, audited reconciliation before retry.
- **Cross-platform float differences** can change artifact hashes between CPU architectures (see [architecture.md](architecture.md#reproducibility)). Exact replay also requires the recorded source and dependency runtime, not just the same operating system.

## Added regression evidence (2026-09-27)

The original threat tests above are supplemented by `tests/test_remediation_http.py` (streamed request limits/readiness), `test_remediation_workflow.py` (stale approvals, crash recovery, owner fencing and audit atomicity), `test_remediation_judgment.py` (numeric grounding, transactional spending, late/refusal usage), `test_remediation_quant.py` (finite semantic lineage and execution), and the skills/evaluation regression suite. See the [remediation report](audits/2026-09-27/remediation.md) for fresh results.

- **Provider assumptions:** reservations use reviewed pricing and a conservative token bound. Provider accounting changes and actual billed usage require live verification. Reconciliation trusts the local operator's confirmed usage; it is audited, not automatically inferred.
- **Semantic limits:** typed citations and numeric field binding cannot prove arbitrary qualitative statements. The scoped automated committee is not a completed external red-team review; excluded stress tests must stay visible.
- **Publication residues:** fencing prevents stale database publication. A write-once blob uploaded before a later transaction failure may remain unreferenced; it is never selected as current evidence by that failed transaction.
